# 2026-03-01

## Bugfix: today-\* commands not auto-creating daily notes

All three `today-*` commands (`today-capture`, `today-daily-capture`, `today-thought`) were still using `findTodaysNote()` (which only searches, never creates) instead of `findOrCreateTodaysNote()`. Fixed all three to use the async version that auto-creates the note when `autoCreateDailyNote` is enabled.

### Changed files

- `src/app/commands/today-capture-command.ts` — switched to `findOrCreateTodaysNote()`
- `src/app/commands/today-daily-capture-command.ts` — switched to `findOrCreateTodaysNote()`
- `src/app/commands/today-thought-command.ts` — switched to `findOrCreateTodaysNote()`

## Daily note picker for "Today's meal" command

Added `DailyNoteSuggestModal` — a `FuzzySuggestModal` that lists all daily notes in the vault (most recent first). The "Today's meal" command now opens this picker instead of going straight to today's note.

- If today's note doesn't exist and `autoCreateDailyNote` is enabled, a "+ Create today's note" option appears at the top
- Uses `obsidian-daily-notes-interface` `getAllDailyNotes()` to enumerate notes; fallback scans YYYY-MM-DD filenames in `dailyNotesFolder`
- Today's entry is bold; the create sentinel is accent-colored
- After selection, the `MealModal` opens on the chosen file

### New files

- `src/app/components/modals/daily-note-suggest-modal.ts` — `DailyNoteSuggestModal`

### Changed files

- `src/app/commands/today-meal-command.ts` — now uses `DailyNoteSuggestModal` instead of `findOrCreateTodaysNote()`
- `src/styles.src.css` — added `lt-suggest-create` / `lt-suggest-today` CSS classes

## Multi-image support in meal modal

Rewrote the image analysis view in `MealModal` to support multiple food images at once:

- **File input**: now accepts `multiple` files
- **Drag & drop**: accepts multiple images in a single drop
- **Clipboard paste**: collects all image items from clipboard
- **Parallel analysis**: each image is analyzed independently and concurrently
- **Results list**: each image shows as a card with status (analyzing / done / error / accepted)
- **Per-card actions**: Accept, Edit (opens manual form pre-filled), Dismiss
- **Accept all**: when 2+ results are ready, an "Accept all (N)" button appears to save them in one batch
- **Progress indicator**: shows how many images are still being analyzed
- **Additive**: user can drop more images while previous ones are still analyzing

### Internal changes

- `isAnalyzing: boolean` replaced with `analyzingCount: number` for parallel tracking
- New `analysisItems: ImageAnalysisItem[]` array tracks per-image state
- New `addMeals()` method for batch saving
- Old single-result methods (`showAnalysisResult`, `showAnalysisError`, `processImageFile`) replaced by card-based rendering (`renderAllAnalysisItems`, `renderAnalysisCard`, `analyzeOneImage`, `processImageFiles`)
- CSS: old `lt-meal-analysis-result/status/error` classes replaced with card-based `lt-meal-analysis-card` system with modifier classes (`--analyzing`, `--accepted`, `--error`)
