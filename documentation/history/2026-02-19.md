# 2026-02-19

## Changes

### Unified priority-to-XP mapping across all TickTick services

- All 3 files now use the same mapping: high(5)=15xp, medium(3)=10xp, low(1)=5xp, none(0)=1xp
- Previously `DirectParser` used `{0:1, 1:5, 3:10, 5:15}` while `ToManualConverter` and `SyncService` used `{0:5, 1:5, 3:15, 5:25}`
- Files changed: `TickTickDirectParser.ts`, `TickTickToManualConverter.ts`, `TickTickSyncService.ts`

### Removed undone task fields from frontmatter output

- `postProcessResult()` now deletes: `tasks_undone`, `sprint_tasks_undone`, `habits_undone`, `task_count_undone`, `total_habits_undone`
- These fields remain in the `TickTickParserResult` interface for internal use (AI summary reports still have access)
- Updated Business Rules to document both changes

### Added timezone support to HCGateway and TickTick integrations

- Added shared `getTimezoneOffset(dateStr, timeZone)` utility to `date.utils.ts` — computes UTC offset from IANA timezone via `Intl.DateTimeFormat`
- **HCGateway**: Added `timeZone` field to `HCGatewaySettings` (default: `Asia/Almaty`). All date boundary queries now include the timezone offset (e.g., `2026-02-19T00:00:00+05:00`). Falls back to naive datetime strings if timezone is invalid.
- **TickTick**: Added `timeZone` field to `TickTickSettings` (default: `Asia/Almaty`). Task date/time display (`formatTaskDate`) now converts TickTick UTC timestamps to the configured timezone. API query format unchanged (naive strings). Replaced hardcoded `America/New_York` fallback pattern.
- Both integrations have a new "Timezone" text input in settings UI
- Files changed: `date.utils.ts`, `hcgateway-settings.types.ts`, `HCGatewaySyncService.ts`, `ticktick-settings.types.ts`, `TickTickDirectParser.ts`, `TickTickAPIService.ts`, `property-capture-modal.ts`, `settings-tab.ts`

### Fixed TickTick focus duration units

- TickTick heatmap and distribution APIs return durations in **minutes**, not seconds
- Removed incorrect `/60` conversions in `TickTickAPIService.parseTasksForDateRange()`
- Removed `focus_total_seconds` key from output (was actually minutes, misleading)
- Distribution values now stored directly as minutes instead of dividing by 60
- Updated all JSDoc comments and type definitions (`IFocusHeatmapEntry`, `IFocusDistribution`)

### Added "Today's capture" and "Today's thought" commands

- New `today-capture` command: auto-finds today's daily note (YYYY-MM-DD) and opens property capture carousel
- New `today-thought` command: auto-finds today's daily note and opens thought capture modal
- Added `dailyNotesFolder` setting (default: empty = vault root) with folder autocomplete
- Shared `findTodaysNote()` utility searches configured folder for today's note
- New `today-daily-capture` command: auto-finds today's note, opens form-style all-fields modal
- Files added: `today-capture-command.ts`, `today-daily-capture-command.ts`, `today-thought-command.ts`, `today-utils.ts`
- Files changed: `plugin-settings.intf.ts`, `settings-tab.ts`, `commands/index.ts`

### Added standalone sync and AI analysis commands

- `sync-ticktick`: Fetches TickTick data for the active file's date, writes to frontmatter (no capture modal)
- `sync-hcgateway`: Fetches HCGateway health data for the active file's date, writes to frontmatter (fresh login each time)
- `analyze-note`: Reads all frontmatter from the active file, sends to AI for analysis, shows result in modal
- All three work on the currently open markdown file, validate prerequisites (enabled, authenticated, etc.)
- Files added: `sync-ticktick-command.ts`, `sync-hcgateway-command.ts`, `analyze-note-command.ts`

### Tests updated

- `TickTickConverter.spec.ts` updated to match new XP values (medium=10 instead of 15, high=15 instead of 25, none=1 instead of 5)
